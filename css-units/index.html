px을 rem으로,
반응형 단위 변환

요즘 웹은 px 대신 rem·vw를 씁니다. 루트 폰트와 뷰포트만 넣으면 어떤 단위로든 바꿀 수 있습니다.

  • 🟢 rem 루트 기준
  • 🟡 em 부모 기준
  • 🔴 vw 뷰포트 기준
16px기본 루트
1vw뷰포트 1%
62.5%10px 트릭
📐

1rem은 html 요소의 font-size, 1em은 현재 요소의 font-size를 기준으로 합니다. 루트를 62.5%(10px)로 두면 1.6rem = 16px처럼 계산이 쉬워지는 트릭이 널리 쓰입니다.

STEP 2

단위별 환산

같은 크기를 px·rem·em·vw·pt로 바꾼 값입니다.

vw·vh는 스크롤바 포함 여부와 모바일 브라우저의 주소창 높이에 따라 실제 렌더링이 달라집니다. 모바일에서는 vh 대신 dvh(동적 뷰포트)를 쓰면 주소창 변화에 대응됩니다.

GUIDE

CSS 단위, 언제 무엇을 쓰나

px·rem·em·vw의 차이와 반응형 전략을 정리했습니다.

01 절대 단위와 상대 단위

단위기준쓰는 곳
px고정 픽셀테두리·아이콘
rem루트(html) 폰트글자·여백 (권장)
em부모 폰트컴포넌트 내부 비율
%부모 크기레이아웃 폭
vw·vh뷰포트전체 화면 히어로

rem은 사용자가 브라우저 글자 크기를 키워도 함께 커져 접근성에 유리합니다.

02 em이 위험한 이유

em은 부모의 font-size를 기준으로 합니다. 중첩되면 크기가 곱해져 예측이 어려워집니다.

부모 16px → 자식 1.2em = 19.2px
그 자식의 자식 1.2em = 23.04px (16 × 1.2 × 1.2)

그래서 여백·글자는 rem, 특정 컴포넌트 내부의 비율만 em으로 쓰는 것이 안전합니다.

03 반응형: clamp()와 dvh

  • clamp(최소, 선호, 최대): font-size: clamp(16px, 2.5vw, 24px)처럼 쓰면 화면 폭에 따라 자연스럽게 변합니다.
  • dvh: 모바일 주소창이 접히고 펴질 때 vh가 흔들리는 문제를 해결합니다.
  • cqi(컨테이너 쿼리 단위): 부모 컨테이너 기준으로 크기를 정합니다.
  • vw는 스크롤바 폭을 포함해 가로 스크롤이 생길 수 있습니다. 100vw 대신 100%를 쓰세요.

04 시안을 코드로 옮길 때

디자인 시안(1440px 기준)을 그대로 px로 옮기면 모바일에서 깨집니다.

  • 글자는 rem, 여백은 rem·%, 아이콘·테두리는 px로 구분하세요.
  • 컨테이너 폭은 max-width + %로 두고, 남는 여백은 자동으로 처리합니다.
  • 반응형 글자는 clamp(1rem, 2.5vw, 1.5rem)처럼 최소·최대를 함께 지정합니다.

FAQ

자주 묻는 질문

16px은 몇 rem인가요?

루트가 16px이면 1rem입니다. 24px은 1.5rem, 14px은 0.875rem입니다. 루트를 62.5%(10px)로 바꾸면 16px은 1.6rem이 됩니다.

rem과 em은 무엇이 다른가요?

rem은 항상 html(루트) 폰트 크기를 기준으로 하고, em은 현재 요소의 부모 폰트 크기를 기준으로 합니다. em은 중첩되면 곱해져 계산이 어려워집니다.

vw는 어떻게 계산하나요?

뷰포트 폭의 1%입니다. 화면이 1,440px이면 1vw = 14.4px, 5vw = 72px입니다. 모바일 390px에서는 1vw = 3.9px로 확 작아집니다.

모바일에서 100vh가 넘치는 이유는?

모바일 브라우저의 주소창이 차지하는 높이 때문에 vh가 실제 보이는 영역보다 커집니다. 100dvh를 쓰면 동적 뷰포트에 맞춰집니다.

pt는 언제 쓰나요?

인쇄용 스타일시트에서 씁니다. 1pt = 1/72 inch이고, 화면에서는 1pt ≈ 1.333px입니다. 웹 화면에는 권장하지 않습니다.
